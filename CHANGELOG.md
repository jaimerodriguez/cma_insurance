### Added
- 2026-07-24: `requirements.txt` (runtime: `anthropic`, `python-dotenv`) and `requirements-dev.txt` (includes runtime via `-r`, plus `PyYAML` for the `gen_cma_yaml.py` generator). Updated the README setup steps to install via these files.
- 2026-07-24: `README.md` — project overview, architecture, domain model, roles/RBAC, the auto-approval + authorization-routing logic, setup, and usage for both front-ends (`repl.py` test bed incl. dry runs, and `cma.py` Managed Agents), with a file/data map. Distilled from the codebase and `CHANGELOG.md`.
- 2026-07-24: `/agent-run --dry-run` (also `-n`) in `repl.py` — previews route + triage + close by executing the real code path inside a `data/` snapshot/rollback (`_rolled_back_data` context manager), so nothing is persisted. The run is re-runnable and safe to compare across policies; report wording switches to conditional ("would route & escalate …") and is tagged `[DRY RUN — no changes written]`.
- 2026-07-24: Made `repl.py` a local test bed for the AGENT persona. New `/agent-chat` (assume the AGENT role and drive route/triage via the LLM), `/agent-run` (deterministic route + triage + close through `process_incident`, no LLM/key), and `/policies [name]` to view/select mock `DynamicPolicies` (`default`/`no-assign`/`generous`) that stand in for Managed Agents memory. The existing `/agent` still runs only the close-stale pass. The selected mock policy is injected into the AGENT system prompt (so the LLM passes it to `process_incident`) and used by the offline `run_agent_route_and_triage`. Set sample authorization levels in `adjusters.json` (`sam`→MEDIUM, `jane`→HIGH; `jaime` stays LOW) so routing has targets.

### Changed
- 2026-07-24: `process_incident` no longer escalates unassigned incidents to the `"unassigned"` placeholder. When a claim isn't auto-approved it now branches on `DynamicPolicies.can_assign`: an unassigned incident is routed to a suitable adjuster when `can_assign` is True (and left untouched when False or when no adjuster has sufficient authorization); an incident that already has an adjuster still escalates. Added `can_assign` (default `False`) and cost limits `authorization_low`/`authorization_medium`/`authorization_high` (500/1500/5000) to `DynamicPolicies`, plus `DynamicPolicies.required_authorization(cost)` mapping a cost to the minimum `AuthorizationLevel`. Routing picks the lowest-authorization adjuster that qualifies via a new internal `tools._select_adjuster` helper.

### Added
- 2026-07-24: Expanded the `AGENT` maintenance persona to route and triage claims. Rewrote `_AGENT_PROMPT` (`roles.py`) to delegate routing to `process_incident`: the agent lists `"unassigned"` incidents and calls `process_incident` with `{"can_assign": true}`, which auto-approves, routes to an authorization-appropriate adjuster, or escalates — calling it again on a just-assigned incident to reach a decision, and reporting any claim whose cost exceeds every authorization limit as needing manual routing. (Supersedes the earlier draft that had the agent route manually with hardcoded cost bands; the authoritative limits now live in `DynamicPolicies`.) Granted the `AGENT` role `process_incident` and a new `list_adjusters` tool.
- 2026-07-24: `list_adjusters()` in `tools.py` — returns the full adjuster roster so the agent can route by `authorization_level`. Registered in `AGENT_TOOLS`.
- 2026-07-23: `assign_incident(incident_id, adjuster_id)` in `tools.py` — reassigns an incident to an adjuster and appends a date-stamped history note. Validates the adjuster exists (returns `None` if the adjuster or incident is unknown). Registered in `AGENT_TOOLS` and granted to the `AGENT` role (`roles.py`), along with `find_adjuster`/`get_adjuster_details` so the agent can pick an assignee. Regenerated `agent_tools_schema.json`.
- 2026-07-23: `AuthorizationLevel` (`StrEnum`: `LOW`/`MEDIUM`/`HIGH`) in `data_entities.py`, and an `authorization_level` field on `Adjuster` (defaults to `LOW`) for the agent to use when assigning incidents to adjusters. `Adjuster.__post_init__` coerces a plain string (as loaded from JSON) into the enum; existing `adjusters.json` entries default to `LOW`.
- `.env` file with an `ANTHROPIC_API_KEY` placeholder and a matching `.env.example`.
- `.env` loading in `manaul_setup.py` via `python-dotenv` (`load_dotenv()`), so the Anthropic SDK picks up the key automatically.
- Guard in `main()` that exits with a clear message when `ANTHROPIC_API_KEY` is missing or still the placeholder.
- `.gitignore` excluding `.env`, `.key`, and Python artifacts.

- 2026-07-24: Added the `ant` CLI / version-controlled control-plane path for the Managed Agents setup. `gen_cma_yaml.py` generates, under `cma/`, the environment YAML, one agent YAML per role (tools + system prompt embedded, generated from the same `cma`/`roles`/`agent_schemas` code so they can't drift), adjuster memory seed files, and `setup.sh`. `setup.sh` applies them via `ant beta:environments/agents create`, provisions and seeds the memory stores via `ant beta:memory-stores`/`:memories` (beta `agent-memory-2026-07-22`, set automatically by the CLI), and writes `data/cma_config.json` — the same config `cma.py` consumes at runtime. Generation is round-trip-validated (YAML reloads to the exact bodies) and the emitted config JSON was verified valid; `cma.setup()` (SDK) and `cma/setup.sh` (CLI) are interchangeable ways to provision the same resources. (PyYAML is a dev-only dependency of the generator, not of the runtime.)
- 2026-07-24: Added a Managed Agents (CMA) front-end, `cma.py`, that uses Managed Agents memory stores for adjuster memory. `setup()` idempotently provisions a cloud environment, one agent per role, and one `memory_store` per adjuster (seeding jaime's policy overrides), persisting IDs in `data/cma_config.json`. `CmaSession` creates a session per role/identity (adjuster sessions attach the adjuster's memory store, mounted at `/mnt/memory/<store>/`, and use an identity-specific `agent_with_overrides` system prompt), streams events, and dispatches `agent.custom_tool_use` events to the role-restricted `tools.py` functions (declared as CMA custom tools). Adjuster agents also get the prebuilt `agent_toolset_20260401` so they can read/write their memory store; the maintenance agent closes stale resolved claims. Reuses `roles`, `agent_schemas`, and the `repl` dispatcher so the hosted and local paths stay in lockstep. Verified by offline inspection (tool defs, prompts, config); run in an MA-enabled workspace via `python3 cma.py` then `/setup`.
- 2026-07-24: Added a role-based CLI REPL (agent chat) front-end and the shared role logic behind it.
  - `data_entities.py`: added `Incident.resolved_date` (UTC datetime, set when a claim is approved/denied) with matching (de)serialization.
  - `tools.py`: `update_resolution` now stamps `resolved_date` on APPROVED/DENIED; added `list_incidents_for_insurer(insurer_id)` and `close_stale_resolved(minutes=30)` (auto-closes claims resolved longer than the threshold), both registered in `AGENT_TOOLS` (now 27 tools).
  - `roles.py`: RBAC shared by the REPL and the agent — per-role tool allow-lists (`ADJUSTER`/`INSURER`/`AGENT`), `tools_for_role`/`schemas_for_role`/`dispatch_table`, and `build_system_prompt` that seeds each persona (adjuster prompt embeds the memory-overridden `DynamicPolicies`; insurer prompt is personalized and can only file/query its own claims).
  - `agent_memory.py`: `data/agent_memory.json` store of per-adjuster `DynamicPolicies` overrides + notes; `effective_policies()` merges them over the defaults. Seeded a sample for `jaime`.
  - `repl.py`: the REPL loop (`/adjuster <name>`, `/insurer <id>`, `/agent`, `/whoami`, `/reset`, `/help`, `/quit`). Uses the Anthropic SDK (`claude-opus-4-8`, adaptive thinking, manual tool loop) with role-filtered schemas and a role-restricted dispatcher; `SYSTEM_PROMPT_EXTRA` is the hook for adding tone. `/agent` runs `close_stale_resolved` deterministically (no API/key needed).
- 2026-07-23: Made `process_incident`/`escalate_incident` accept `policies` as a `DynamicPolicies`, a plain dict, or None. Added `DynamicPolicies.coerce()` to normalize the three (unknown dict keys ignored), so an agent tool-call dispatcher can pass the JSON object straight through without constructing the dataclass. Schema output is unchanged (the object schema still wins over `dict`).
- 2026-07-23: Added `agent_schemas.py`, which introspects `tools.AGENT_TOOLS` (signatures + type hints + Google-style docstrings) to generate Anthropic Messages API tool schemas (`{name, description, input_schema}`). Handles nested dataclass params as object schemas (`DynamicPolicies`), `StrEnum` params as string enums, and `IntFlag` (`ReportType`) as an integer bitmask with member values. Running it writes `agent_tools_schema.json` (25 tools).
- 2026-07-23: Added a `DynamicPolicies` dataclass (`data_entities.py`) holding tunable auto-approve ceilings (`auto_approve`, `vip_auto_approve`, `upset_auto_approve_home`, `vip_auto_approve_home`) plus `agent_override_autoapprove`/`agent_override_autoapprove_reason`. Its `should_auto_approve()` method returns `(approve, reason)` using the highest applicable ceiling (VIP status from the insurer record, HOME policy type, upset flag), with the agent override short-circuiting to approve. Reworked `approve_incident` to take a `DynamicPolicies` (defaulting to `DynamicPolicies()`) and delegate the decision to it, recording the reason on `resolution_reason`; `escalate_incident` also now accepts the policies object. Added an optional `reason` parameter to `update_resolution`. Removed the obsolete `AUTO_APPROVE_UNDER`/`UPSET_APPROVE_UNDER` constants.
