## [Unreleased]

### Added
- 2026-07-27: **New tool `generate_unassigned_incidents(count)`** (32 tools now) — regenerates the claim set on demand, so a deployed server can reset itself for a demo or a load test without a redeploy. Replaces the hand-built `data/synthetic-incidents-*-unassigned.json` fixtures as the way to get a fresh batch of unrouted claims. Takes `count` between 5 and 50 inclusive; out-of-range values are rejected, never clamped.
  - **Granted to AGENT only.** It wipes and rewrites `incidents.json` wholesale, which is a setup operation rather than claims work — an adjuster must never be able to discard the claims it is being asked to handle. Enforced by the dispatch table, not just by which schemas each role is offered; there are tests for both.
  - **No change to `mcp_server.py` was needed.** Registering the function in `tools.AGENT_TOOLS` and `roles.ROLE_TOOLS[AGENT]` is enough for it to appear on the REPL, the `--use-key` loop, Managed Agents custom tools, and the `/mcp/agent` endpoint at once. That the facade required zero edits to absorb a new tool is the property it was built for. The AGENT endpoint goes 11 tools → 12.
  - **Generated claims are internally consistent, which the old fixtures were not.** The policy is drawn from the real policies on file and the insurer is the one that actually holds it, so `find_policy` and `find_insurer` cannot disagree during triage. The loss type is matched to the policy type — vehicle losses on auto policies, dwelling losses on home policies — where the checked-in fixtures predate the `HOME_*` report types entirely and only ever carry the three vehicle/theft flags. Costs are drawn to straddle the 5000/15000/50000 authorization limits, so a batch exercises every band including the `OVERRIDE_NEEDED` → `ESCALATED_TO_MANAGEMENT` path.
  - **Bounds are validated before the wipe.** Checking after would mean a caller who asked for 51 lost the claims they already had; there is a test that asks for 51 and asserts the existing set is untouched. A `bool` is rejected explicitly — `True` is an `int` in Python and would otherwise pass a range check as 1.
  - **Returns a summary, not the claims.** Fifty full records is thousands of tokens the caller did not ask for; `list_incidents` reads them back. Keyed by `report_type.name` rather than `str()`, since `IntFlag.__str__` is `int.__str__` and would label the batch "5" instead of "STOLEN_CAR|CAR_ACCIDENT".
  - Ids are drawn from `random` rather than `uuid4`, so seeding the module reproduces a batch exactly — which is what makes the generator testable and a demo repeatable.
  - `storage.replace_incidents` is a new public, deliberately blunt name for the existing private `_write_incidents`. Every other writer in `storage.py` is read-modify-write and preserves the rest of the file; this one does not, so the call site has to say the destructive word out loud.
  - 29 new tests (439 total). Mutation-checked against six mutations — raising the ceiling to 500, moving the wipe before the bounds check, picking the insurer at random instead of from the policy, ignoring the policy type when choosing the loss, dropping the `bool` guard, and granting the tool to ADJUSTER — each failing the intended tests and only those.
- 2026-07-27: **Container deployment for `mcp_server.py` on Azure Container Apps** — `Dockerfile`, `entrypoint.sh`, `.dockerignore`, `requirements-mcp.txt`, and `ACA_Deploy.md`. Additive only: `python3 mcp_server.py` under uvicorn is unchanged and remains the default, and with an untouched `.env` nothing about the running app differs.
  - **Container Apps rather than Azure Functions, after evaluating both.** Functions' MCP extension declares tools through `mcpToolTrigger` with a flat `toolProperties` vocabulary — `propertyName` / `propertyType` ∈ {string, number, integer, boolean, object} / `isRequired` / `isArray`. It cannot express `enum`, nested object properties, or type unions, so it would have discarded `agent_schemas.build_tool_schemas()` and silently regressed the `["string","null"]` nullable fix this CHANGELOG records as a live defect — the same trap that ruled out `FastMCP`. It also mismatches auth: the extension gates on an `x-functions-key` system key while the Managed Agents vault sends `Authorization: Bearer`. Hosting the existing Starlette app via `func.AsgiFunctionApp` would have avoided the schema loss, but `azure-functions`' ASGI shim buffers response bodies (`self._buffer.append(...)` … `b"".join(self._buffer)`, commented "Chunked bodies not supported"), so SSE never flushes. Container Apps runs `mcp_server.py` unmodified, streams properly, and still scales to zero.
  - **`storage.DATA_DIR` now honours `CLAIMS_DATA_DIR`.** The one source change, and only because a container image is read-only: a deployment whose writes must survive a restart has to point the stores at a mounted volume. Read once at import so the existing tests keep patching the module globals directly. `agent_memory.AGENT_MEMORY_FILE` derives from it and follows for free.
  - **`entrypoint.sh` seeds per file, never per directory.** A volume holding a half-written world — `incidents.json` present, `adjusters.json` absent after an interrupted first boot — passes a directory-level emptiness test and then serves an adjuster-less world. Existing files are never overwritten, so a restart tops up a partial volume instead of resetting a live one.
  - **`--max-replicas 1` is a correctness constraint, not a cost setting**, and `ACA_Deploy.md` says so: `_STORAGE_LOCK` is a `threading.Lock` that serializes writes within one process, and `storage.py` is whole-file read-modify-write, so a second replica loses the first's writes across unrelated records.
  - **`requirements-mcp.txt` is deliberately not `-r requirements.txt`.** The server needs neither `anthropic` nor `claude-agent-sdk`; `repl.py` is in the image only for `_dispatch`, and its Agent SDK imports are function-local so they never fire. Keeping the list separate means a dependency added for the client does not silently join the deployed server.
  - **The default deployment resets state on scale-to-zero** — writes land in the container's writable layer. Documented rather than hidden, since for a demo a known starting state is usually the desired behaviour; the Azure Files path is written up for when it is not, along with its two costs (SMB round trips per whole-file rewrite, and a shared volume making the single-replica constraint load-bearing twice over).
  - 8 new tests (404 total). The two that earn their keep check failure modes invisible until a cold start in Azure: every first-party module in `mcp_server`'s real import closure is COPYed into the image, and every direct third-party import is installable from `requirements-mcp.txt`. The closure is measured by importing in a clean interpreter and reading `sys.modules`, not by parsing `import` statements, so function-local imports stay out and re-exports stay in. Mutation-checked: dropping `storage.py` from the COPY, dropping `jsonschema` from the requirements, making the entrypoint overwrite unconditionally, and reverting the `CLAIMS_DATA_DIR` override each fail the intended test and only that test.
  - Live-verified locally against a running server: `/healthz` reports 21/8/11, `401` without a token and `200` with one, `tools/list` on `/mcp/insurer` returns exactly its 8 tools, a call to a name outside the role is refused server-side, a bad argument produces the traced validation error, and a real `find_insurer` call returns real data read through `CLAIMS_DATA_DIR` with `tool.start`/`tool.end` written under `OBS_VAR_DIR`. **The image itself has not been built or deployed** — no Docker daemon was available in this environment.
- 2026-07-27: **`mcp_server.py` — the 31 domain tools served over streamable HTTP**, so Anthropic's orchestration layer can call them directly instead of handing each call back to us as a Managed Agents custom tool. Off by default: with an untouched `.env` the custom-tool path is byte-identical (verified by diffing `_desired_agent` against `main` — every pre-existing field matches, the only addition is `mcp_servers: []`).
  - **A facade, not a reimplementation.** Every call lands on `repl._dispatch` against a `roles.dispatch_table`; `tools.py`, `storage.py` and `agent_schemas.py` are untouched, and tracing comes free from `@agent_obs.traced_dispatch`. A test asserts the served schemas equal `cma.custom_tools_for_role` minus its `type` discriminator, and another asserts a result over the wire is byte-identical to calling `_dispatch` directly.
  - **`FastMCP` deliberately not used.** Its `add_tool` derives input schemas from Python signatures via pydantic with no override, which would silently replace `agent_schemas.build_tool_schemas()` — losing the docstring parsing, the `ReportType` bitmask descriptions, and the nullable-optional fix this CHANGELOG records as a live defect. The low-level `mcp.server.lowlevel.Server` publishes our schemas verbatim, which is the only way this stays a facade.
  - **One endpoint per role**, each serving only `roles.schemas_for_role(role)`. This *recovers* what `roles.DELEGATES_TO` gave up: an MCP subagent calls its own endpoint, so the AGENT endpoint is exactly its 11 tools rather than the AGENT ∪ ADJUSTER union of 25.
  - **Not a latency win, and the code says so.** Tools are local file I/O at 2-9 ms; MCP replaces that with a network round trip. It is adopted for availability — unattended runs with no local process on the session.
  - **Validation happens in our seam, not the MCP server's.** `call_tool(validate_input=True)` rejects *before* the handler runs, producing no `tool.start`/`tool.end` pair — the exact blind spot that made the nullable-schema defect hard to see. `validate_input=False` plus a check inside the handler keeps every failure mode traced and identically shaped.
  - **`Mount` per role would have broken it.** Starlette 307-redirects the bare `/mcp/agent` to a trailing slash and the MCP client does not follow, so the prefix is mounted once and the role segment matched by hand. Regression test included; found by the live client failing, not by reasoning.
  - Auth is a static bearer token via pure-ASGI middleware (`hmac.compare_digest`; not `BaseHTTPMiddleware`, which buffers responses and breaks streaming). `cma.ensure_vault` reconciles one vault credential per endpoint URL — keyed by URL because the URL is what moves when the server is re-homed — and `_create_session` passes `vault_ids`. The server refuses to start without a token.
  - `cma.py` gains `mcp_tools_for_role` / `mcp_servers_for_role`, `mcp_servers` in `_desired_agent` and drift detection, and `/mcp`. `mcp_servers` is always sent including as `[]`, since switching back to custom tools has to *clear* the declaration rather than leave a stale URL.
  - `mcp`, `starlette` and `uvicorn` are now declared in `requirements.txt` rather than leaned on transitively via `claude-agent-sdk` — the Managed Agents front-end is meant to work without the Agent SDK.
  - 33 new tests. Live-verified end to end: server boots, `/healthz` reports 21/8/11, 401 without or with a wrong token, real MCP sessions list the right tools per role, a real call returns real data, and the server writes its own `mcp-*` trace with `tool.start`/`tool.end`. Mutation-checked: removing the storage lock fails 2 tests, including the one that loses writes.

### Fixed
- 2026-07-27: **`EventLog.debug/info/warn/error` crashed on a field named `level`.** `event`'s `level` is keyword-only, so `debug(name, level=…)` raised `got multiple values for keyword argument 'level'` *before* the reserved-key renaming at the bottom of `event` could run — the same collision class that made `name` positional-only, one keyword over. It was not theoretical: `install_logging` passes `level=` and took the MCP server down at startup. The wrappers now route through `_at`, which renames a caller's `level` to `field.level` — exactly what `event` would have done — so the field is preserved rather than fatal. `logbridge` also now says `threshold=`, since `field.level` reads as an accident.
- 2026-07-27: **Managed Agents turns spent ~90 of every 100 minutes blocked on a dead socket.** `CmaSession.send` treated `session.status_idle` with `stop_reason.type == "requires_action"` as "keep reading" (`# Idle waiting on us (a custom tool) -> keep going`). But `requires_action` means the session is blocked on *us* and will emit nothing further until we answer — so the loop read on until httpx's default 600 s read timeout (`anthropic/_constants.py`: `httpx.Timeout(timeout=10 * 60)`, never overridden at `cma.py`'s client construction) killed the connection. Only then did the `with` exit, results get posted, and the next leg repeat it.
  - **Measured, from `var/traces/cma-20260727-100909-3460bb.*`:** 10 SSE stream requests totalling **111.7 minutes**, individual durations `677151, 603730, 626984, 759553, 623308, 618542, 724144, 685945, 675836` ms — while the **39 tool calls in that same run summed to 44 ms** (max 9 ms). Every non-stream request was 200–830 ms. Tool execution was ~0.0007% of the run.
  - **The fix is set-coverage against `stop_reason.event_ids`**, not a heuristic. `BetaManagedAgentsSessionRequiresAction` documents the contract: *"The ids of events the agent is blocked on. Resolving fewer than all re-emits `session.status_idle` with the remainder."* For a custom tool the blocking event *is* the `agent.custom_tool_use` event, whose `id` is what we already echo back as `custom_tool_use_id`. The leg ends as soon as the collected ids cover the named set.
  - Coverage is re-checked in **two** places, because the idle can arrive either before or after the calls it names. Checking only on the idle event — the obvious implementation — hangs whenever the ordering is reversed; there is a test for exactly that.
  - An uncovered id means keep reading: answering a partial set would strand the session. Absent or empty `event_ids` falls back to the previous batch behaviour rather than hanging, so an API shape change degrades safely.
  - `STREAM_TIMEOUT_S = 300.0` is now passed explicitly to `events.stream()` as a **backstop**, not the mechanism — a healthy turn never reaches it. It sits below the SDK's 600 s default so any *other* silent stream costs seconds instead of ten minutes, and above the longest legitimate inter-event gap, since the model can think for minutes without emitting.
  - New `cma.idle` event records `stop_reason.type` and the blocked-on count. `cma.py` previously logged only `event_type`, which is why the events log could not distinguish "idle, waiting on us" from "idle, done" after the fact — that gap is why this took a trace-level investigation to find.
  - **Not** fixed by moving the tools to an MCP server, which was the original plan: MCP would have removed the stall only as a side effect of deleting the code path containing it, at the cost of a VM, a public endpoint, auth, and relocating `data/` — and would have made the component it actually governs slower, turning 39 sub-10 ms local calls into 39 network round trips. That work is now scoped on its own merits (unattended runs, server-side data) rather than latency.
  - Six new tests in `tests/test_cma_agents.py` drive `send()` over scripted event streams and assert on how many events were *consumed*, since a real stream would block rather than end. Mutation-checked: restoring the original bug fails 1, dropping the after-the-idle re-check fails 1, answering a partial set fails 2, dropping the explicit timeout fails 1.

### Added
- 2026-07-25: **Adjuster subagents on the Agent SDK backend** — an AGENT session now registers one subagent per adjuster (`adjuster-jaime`, `adjuster-sam`, `adjuster-jane`) via `ClaudeAgentOptions.agents`, and the maintenance agent delegates each claim's *decision* to the adjuster it routed the claim to instead of deciding it itself. Definitions are generated in `repl._adjuster_agents()` from `adjusters.json`, so an adjuster added to the roster gets a subagent with no code change; the `unassigned` placeholder is skipped.
  - **Identity is structural, not advisory.** It is fixed in the definition name and baked into the prompt by `roles.build_system_prompt(Role.ADJUSTER, user_id)` — the same prompt the interactive `/adjuster` persona uses. A generic "you are whichever adjuster the task says" subagent was rejected: the tools take `adjuster_id` as an argument, so nothing would stop a subagent told it was jaime from acting as sam. The subagent prompt adds `_SUBAGENT_EXTRA`, which lifts the interactive "confirm before denying / bulk-approving" rule (a subagent has nobody to confirm with, so that instruction would otherwise be silently contradicted rather than resolved) and pins the agent to its own adjuster id.
  - **`roles.session_roles` / `DELEGATES_TO`.** Subagents resolve their tools against the single MCP server the session registers, so `_build_sdk_server` now builds from the session role *plus* the roles it delegates to — AGENT sessions serve the AGENT ∪ ADJUSTER union (25 tools, up from 11). Each subagent is narrowed back to the 21 ADJUSTER tools by its `AgentDefinition.tools`; the 4 agent-only tools (`assign_incident`, `close_stale_resolved`, `list_adjusters`, `retrieve_policies`) are withheld. `tools_for_role` / `schemas_for_role` / `dispatch_table` accept a role or an iterable of roles; single-role callers are unchanged.
  - **This weakens one property and the README now says so.** Part of the enforcement moves from "the function is not in the dispatch table" to "the tool is not on this agent's allow-list". `_dispatch` still refuses anything outside the table, but the table is wider than the parent role alone. A `PreToolUse` authorization hook could restore — and exceed — the old guarantee, since tool-lifecycle hooks carry `agent_id`/`agent_type` (`_SubagentContextMixin`) and could reject `update_resolution(adjuster="sam")` coming from `adjuster-jaime`. Not implemented: it would make hooks enforcing rather than tracing-only, which `agent_obs` documents as an invariant, so it belongs in a separate non-observability hook.
  - The built-in **Agent tool is added to `allowed_tools`** only when subagents were registered — without it the definitions exist but are unreachable and the model silently does the work itself. Subagents run on `ADJUSTER_SUBAGENT_MODEL` (`"sonnet"`) while the maintenance agent stays on `MODEL`.
  - **Scoped to the one backend that supports it.** `--use-key` runs the tool loop locally and cannot launch subagents, so it stays single-agent; ADJUSTER and INSURER sessions register none. The delegation section is appended to the AGENT prompt only when the caller passes a non-empty `delegate_agents` roster, so `cma.py` (which has its own coordinator mechanism) is never told to delegate to subagents it does not have.
  - Verified structurally: 3 subagents registered for an SDK AGENT session and 0 for every other role/backend combination, subagent tool set ⊆ server tool set, identity present in each generated prompt, and `ClaudeAgentOptions` accepting the assembled config. **Not yet verified live** — no end-to-end run has confirmed the CLI honours the definitions and actually delegates.
- 2026-07-25: **`tests/test_triage.py` — 47 tests for the triage path**, the first coverage of the domain logic (`tests/` previously held only `agent_obs` tests). Covers auto-approve ceiling selection (baseline / VIP / home / upset / agent override, and the boundary being exclusive), routing to the lowest qualifying adjuster across all bands, the `can_assign` gate, escalation to a claim's own adjuster, the whole management path (cost-driven and adjuster-driven, `can_assign` independence, idempotent re-triage, override precedence, queue withdrawal), terminal-resolution auto-close, and the `AuthorizationLevel` band mapping.
  - **`tests/conftest.py`** adds a `world` fixture that redirects the storage layer at a scratch `data/` seeded with one adjuster per authorization band. It patches every `storage` path constant, not just `DATA_DIR` — the file globals are bound at import, so patching the directory alone leaves reads and writes pointed at the repo's real `data/`. It also puts the project root on `sys.path`, so a bare `pytest tests/` works and not only `python -m pytest`.
  - **Verified by mutation rather than by passing.** Eight regressions were reintroduced one at a time against a scratch copy and the suite had to catch each: `required_authorization` returning `None` again (8 failures), `is_home` narrowed back to the policy type (5), the idempotency guard removed (2), `MANAGEMENT_OVERRIDE` dropped from `is_terminal` (2), the management check moved behind the `can_assign` gate (1), `Adjuster` no longer rejecting `OVERRIDE_NEEDED` (1), and the auto-approve comparison made inclusive (1).
  - The eighth mutation — letting routing select the `unassigned` placeholder — initially **passed**, exposing a vacuous test: with a real LOW adjuster in the roster, the `user_id` tie-break (`"leo" < "unassigned"`) picks the right adjuster whether or not the guard exists. The test now leaves the placeholder as the only LOW candidate, so it fails when the guard is removed.
- 2026-07-25: **`ReportStatus.ESCALATED_TO_MANAGEMENT` and `AuthorizationLevel.OVERRIDE_NEEDED`**, plus the routing that connects them to last change's `Resolution.MANAGEMENT_OVERRIDE`. The full path is now: cost above every band → `OVERRIDE_NEEDED` → status `ESCALATED_TO_MANAGEMENT` → resolution `MANAGEMENT_OVERRIDE` (terminal) → auto-close.
  - **`required_authorization` no longer returns `None`.** Above `authorization_high` it returns `OVERRIDE_NEEDED`; the return type is now plain `AuthorizationLevel`. "Beyond every band" is a real answer the caller must route on, and as `None` it was indistinguishable from "no adjuster is available" — both fell into the same `return incident` and the claim was silently stranded with nobody able to decide it.
  - **`process_incident` checks for `OVERRIDE_NEEDED` before any routing**, ahead of the `can_assign` gate on purpose: `can_assign=False` means "don't pick an adjuster", not "strand a claim nobody may decide". This applies whether or not the incident is already assigned.
  - **New tool `escalate_to_management(incident_id, reason)`** (31 tools now), granted to ADJUSTER and AGENT. Sets the status, stores the reason, logs history, and withdraws any pending adjuster escalation since the decision is no longer theirs. Deliberately *not* a resolution of its own — an escalation is a routing step, and making it an outcome would stamp `resolved_date` and let the auto-close pass close a claim nobody has decided.
  - **`AuthorizationLevel` gained `.rank` and `.is_assignable`,** replacing the `_AUTH_RANK` lookup table in `tools.py` — which would have raised `KeyError` on the new member. `Adjuster.__post_init__` now rejects `OVERRIDE_NEEDED`, so an adjuster ranked above HIGH can never become the routing candidate for claims no one is allowed to decide.
  - **`process_incident` is idempotent for claims already with management** — it returns them untouched. Without this the churn was real and I verified it: these claims stay `INPROGRESS`, so they keep matching the "open incidents" filter, and three triage passes wrote three identical history lines. The guard also outranks `agent_override_autoapprove`, since an escalation to management is precisely the case where the agent stops deciding.
  - `repl.py` distinguishes a fresh escalation from one still pending ("still with management") so a repeated pass does not claim to have escalated the same claim again.
  - No migration: `data/` holds only statuses new/open/closed and adjuster levels low/medium/high.
- 2026-07-25: **Three home-loss `ReportType` flags** — `HOME_THEFT` (8), `HOME_ACCIDENT` (16), `HOME_NATURAL_DISASTER` (32), joining `STOLEN_CAR`/`STOLEN_OTHER`/`CAR_ACCIDENT`. Plus a `HOME` composite alias (`HOME_THEFT | HOME_ACCIDENT | HOME_NATURAL_DISASTER` = 56) so callers can ask "is this a dwelling loss at all?" without naming each member. The alias is deliberately not a canonical member: `Flag` iteration skips aliases, so `agent_schemas` still advertises exactly the six combinable flags and the generated tool description is unchanged in shape.
  - **`is_home` is now broader than the policy type.** `process_incident` computed it as `policy.policy_type == PolicyType.HOME`; it is now that **or** any `ReportType.HOME` flag on the incident. A dwelling loss filed against a non-HOME policy therefore reaches `vip_auto_approve_home` / `upset_auto_approve_home` instead of being treated as a car claim. This raises the auto-approve ceiling for claims that did not previously qualify — verified: a VIP's 9000 claim on an AUTO policy escalates as `CAR_ACCIDENT` (ceiling 2000) and auto-approves as `HOME_THEFT` (ceiling 25000).
  - Existing bitmasks are untouched: `data/` holds only 1, 2, 4 and 5, all still valid, so no migration is needed.
- 2026-07-25: **`Resolution.MANAGEMENT_OVERRIDE`** — management settled a claim outside the normal authorization bands. Serialized as `"management_override"`. It is a **terminal** outcome: it stamps `resolved_date`, clears any pending `Escalation`, and is eligible for the `close_stale_resolved` auto-close pass, exactly like APPROVED and DENIED.
  - **Added `Resolution.is_terminal`** rather than extending three tuples. `tools.py` spelled the rule as `resolution in (Resolution.APPROVED, Resolution.DENIED)` in three places — `update_resolution` twice (stamping `resolved_date`, popping the escalation) and `close_stale_resolved` once — so adding a member meant remembering all three or getting a resolution that silently never closes. The rule now lives on the enum, next to the members it classifies, and the call sites read `resolution.is_terminal`. `INPROGRESS` and `DISPUTED` remain non-terminal, unchanged.
  - Verified end-to-end on a copy of `data/`: an escalated claim set to `management_override` gets `resolved_date` set, leaves the escalation queue, and is picked up by `close_stale_resolved`; a `disputed` claim still gets neither.
  - `repl.py` needed no change — `process_incident` only ever sets `APPROVED`, and its `INPROGRESS` filter correctly excludes a terminal override.

### Fixed
- 2026-07-25: **`cma.py --wire` captured nothing.** The default `wire_paths` was `("/v1/messages", "/v1/beta")`, but Managed Agents resources are plain `/v1/<resource>` paths — `/v1/agents?beta=true`, `/v1/sessions?beta=true`, `/v1/memory_stores?beta=true` — where the beta is a **query parameter and an `anthropic-beta` header, not a `/v1/beta/` path prefix**. No request matched, so the proxy started, forwarded every call correctly, and recorded none of them. There was no error and no empty file, just no wire log at all — confirmed in the user's runs (`cfg.wire=True`, no `cma-*.wire.jsonl`). The default now names each Managed Agents resource alongside `/v1/messages`.
  - **The existing test asserted the same wrong path** (`/v1/beta/sessions/sess_1/events`, which the SDK never sends) and therefore passed while the feature was broken. Replaced with a parametrized test over the five paths the SDK actually requests, plus one that scrapes `/v1/...` literals out of the installed `anthropic` package and asserts the defaults cover them — so a new Managed Agents resource fails loudly instead of going uncaptured.
  - Resources are listed explicitly rather than globbing `/v1/`, so `/v1/oauth/token` — which carries refresh tokens and client secrets — is never captured; a test pins that too.
  - Reverting the default fails 6 tests. Verified live against the real API: a `beta.agents.list()` through the proxy produced `GET /v1/agents?beta=true&limit=2 -> 200 (5796 B, 260 ms)` in the wire log.
- 2026-07-25: **`cma.py` never loaded `.env`, so it could not use an API key.** Only `repl.py` (behind `--use-key`) and `manual_setup.py` called `load_dotenv`; `cma.py` relied entirely on whatever was already in the environment. It happened to work via an `ant auth login` profile, which masked the gap. `main()` now calls `_load_api_key()` before anything else and prints the resolved source at startup (`Auth: ANTHROPIC_API_KEY from .env / environment`). Unlike `repl.py` this is unconditional: Managed Agents is API-only, with no subscription path like the `claude` CLI's.
  - Precedence is preserved rather than forced — `load_dotenv` defaults to `override=False`, so an exported `ANTHROPIC_API_KEY` still beats `.env`, and with no key anywhere it falls through to an `ant auth login` profile instead of exiting (refusing to start would break that path).
  - **A non-`sk-ant-` value is now rejected up front.** An API key outranks a profile in the SDK's resolution order, so a leftover placeholder does *not* quietly fall back to a working profile — it goes out on the wire and returns a 401. This was live: `.env` held a 10-character `ENTER_H…` placeholder, which meant `repl.py --use-key` was loading it over a working profile (the SDK prints its own warning when this happens).

### Added
- 2026-07-24: **`agent_obs/shape.py` — tool-definition shaping on the wire path** (`--obs-wire-tools {full,skeleton,names}`, `OBS_WIRE_TOOLS`; `--obs-wire-tools-keep`, `OBS_WIRE_TOOLS_KEEP`). Opt-in, `full` by default. `skeleton` reduces each tool definition to `{name, params, required, desc_chars, sha}` (~55 bytes); `names` to `{name, sha}`; `keep` holds `fnmatch` patterns exempted from both.
  - **Why.** On the Agent SDK path the `claude` CLI assembles the tool list and ships every native tool plus every MCP server configured on the machine — not only the ones this app registers. Measured on `repl-20260724-161108-7658e9.wire.jsonl`: 118 definitions, 268 KB per request, **95% of the body**, of which 8 tools (4.4 KB) were `mcp__insurance__*`. Worse than the bytes, third-party servers interpolate account state into their descriptions: that capture contained a real Slack user id (15 occurrences) and workspace archive URLs, written to disk under `flow`, `dev`, and `none` alike.
  - **A separate layer from redaction, on purpose.** A `Redactor` decides *how much of a value* to keep and knows nothing about the request schema, which is what lets one mode serve the event log and the wire log. A `Shaper` knows exactly what a `/v1/messages` body is and decides *which parts are worth keeping at all*. Folding tool-name matching into the generic walker would have given `StrictRedactor` a special case it has no use for.
  - **Shapers run before the redactor** (`CaptureProxy._record`), for three reasons: a skeleton's `sha` must cover the original tool, and by the time `flow` is done the description is already a `seen` marker; `strict` summarises `body` wholesale so it must be handed a real structure; and the redactor staying last keeps credential stripping unconditional — a shaper is never a second path to disk. Shaping applies to a parsed copy, while the bytes forwarded upstream are the originals read before any of it runs, so it cannot alter the request the model receives. A shaper that raises degrades to a verbatim capture with `shape_error` set, rather than losing the row.
  - **`keep` takes patterns, not names.** A hand-maintained name list silently drops the schema of any tool added later — exactly the schema you would want. One pattern for the server this app registers (`mcp__insurance__*`) covers tools added next month automatically.
  - **Elision stays auditable.** The per-tool `sha` is over the original canonical JSON, so "did the tool list change between turns?" is still answerable from a shaped trace, and rows are stamped `"_shaped": ["tools:skeleton"]` so a filtered capture can never be mistaken for a faithful one.

### Fixed
- 2026-07-24: **`flow` redaction rewrote resent tool schemas in full on every request**, despite the mode's documented claim that "resent tool schemas … collapse for exactly the same reason the message history does." Only the *descriptions* collapsed. Dedup was per-string, and every string inside a JSON Schema is a field name far below `min_collapse_chars` — so `input_schema` (157 KB of the 268 KB tool payload on the measured run) was written verbatim every turn and no per-string floor could ever catch it. `FlowRedactor` now dedups **subtrees** as well: a dict or list whose canonical JSON exceeds `min_node_chars` and has been written before collapses to `{"_t": "seen_node", "kind", "chars", "sha"}`. Hashing is order-independent (`sort_keys`), registration happens on first sight before children are walked so nested repeats still collapse, and depth 0 is exempt so a row never loses its envelope.
  - `min_node_chars` defaults to 500, above the 200-char string floor: collapsing a string costs its text, collapsing a container costs its *shape* too, and shape is most of what a wire trace is read for.
  - On by default — it is lossless and the `sha` is greppable back to the full copy — with `--no-collapse-structures` / `OBS_COLLAPSE_STRUCTURES=0` as the escape hatch.
  - Replaying the 6-request capture through the real pipeline: **1,059 KB verbatim → 570 KB with `flow` as it was → 263 KB with subtree dedup → 59 KB adding `skeleton` + `keep`.** Per-turn marginal cost of the tool list drops from ~123 KB to ~75 bytes; the shaper's remaining win is on the one-time first sighting, which is why the two are separate switches.
  - Noted while measuring, not fixed here: `strict` now costs about the same as `flow` (263 KB) while showing far less, because `StrictRedactor.wire` summarises wholesale and does not dedup at all.
- 2026-07-24: **`agent_obs` event-field name collisions.** `EventLog.debug/info/warn/error/event` raised `TypeError: got multiple values for argument 'name'` whenever a caller logged a field called `name` — which `trace_callable` did on every deterministic-path call (`/agent-run`, `/agent`, `cma.run_agent_maintenance`), crashing them. Fixed structurally rather than per call site: the event-name parameter on all five `EventLog` methods is now **positional-only** (`name: str, /`), as are `Observability.turn(kind, /)` and `SessionTracer.session/turn/tool`, so an arbitrary field can never shadow a parameter. `Observability.turn` also merges its fields into a dict instead of `kind=kind, **attributes`, so an attribute named `kind` overrides rather than raising. `trace_callable` now logs `func=` instead of `name=`.
  - Found a second bug of the same family while testing: a field named `event`, `ts`, `seq`, `level`, `run_id`, or `session_id` silently **overwrote the row's own envelope** — losing the event name made rows unfindable. The envelope now always wins and a colliding field is preserved under a `field.<key>` prefix, so nothing is lost either way.
- 2026-07-24: **`flow` redaction collapsed short labels.** A 22-char function name was being replaced by a `{"_t": "seen", …}` object roughly three times its length. Added `min_collapse_chars` (default 200, `OBS_MIN_COLLAPSE_CHARS`): strings below the floor are always written verbatim however often they repeat, since a collapsed entry serialises to ~70 characters and short repeated strings are labels (tool/function/model/session ids), not content. Content worth deduplicating is far above the floor.
